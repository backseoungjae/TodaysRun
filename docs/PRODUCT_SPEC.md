# TodaysRun — PRODUCT_SPEC.md

> MVP v1 · 제품 요구사항 명세 · Android 우선

## 1. 제품 목표

**TodaysRun**은 복잡한 설정 없이 러닝을 시작하고 GPS로 시간·거리·페이스·이동 경로를 기록하는 앱이다.

- 핵심 가치: **달리기에 집중하고, 기록은 정확하게.**
- 대상: 러닝 입문자 및 일반 러너
- 저장: 로그인·서버 없이 기기 내 **SQLite(Local-first)**
- 운동: **자유 러닝(Free Run)** 1종
- 제외: 훈련 계획, 목표 모드, 소셜, 음성 안내, 웨어러블, 고급 통계, 클라우드 백업/동기화

## 2. 화면과 내비게이션

| 화면 | 핵심 UX |
| --- | --- |
| **Home** | 상단 햄버거 메뉴·앱 이름·짧은 인사말, 중앙의 큰 원형 `START`. 최근 기록/통계 없음 |
| **Drawer** | `Home`, `Activity`, `Settings` 목록. 하단 탭 없음 |
| **GPS 준비** | Home의 `START`를 인디케이터로 대체. 실패 시 재시도/취소 |
| **Countdown** | Home 위 일회성 전체 화면 오버레이로 `3 → 2 → 1` 표시. 종료 후 사라짐 |
| **Running** | 전체 지도 위 **Draggable Bottom Sheet**. 운동 시간·거리·평균 페이스·경로 및 제어 버튼 |
| **Run Result** | 지도·날짜·거리·운동 시간·평균 페이스. 종료 직후 저장 완료 표시 |
| **Activity** | 최신순 기록 카드(날짜/거리/시간/평균 페이스), 카드 상세 이동, 휴지통 아이콘 삭제 |
| **Settings** | 위치 권한 상태/기기 설정 이동, 백그라운드 기록 토글, 전체 기록 삭제, 앱 소개/버전 |

- `Home → Running → Run Result → 뒤로가기`: **Home**.
- `Activity → 기록 상세(동일 Run Result UI) → 뒤로가기`: **Activity**. 이때 `저장 완료`는 표시하지 않는다.
- Activity의 삭제는 확인 Alert 후 수행; 기록이 없으면 첫 러닝 안내 Empty State 표시.
- Running에서는 Drawer를 노출하지 않는다. Android 시스템 뒤로가기로 운동이 임의 종료되지 않게 보호한다(구체 UI는 구현 전 결정).

## 3. 러닝 시작 흐름

1. Home에서 `START` 클릭 → 위치 권한 및 앱의 백그라운드 기록 사용 여부 확인.
2. 필요한 조건이 부족하면 앱 Alert(`확인`/`취소`). 취소하면 Home 유지.
3. 확인 시 **포그라운드 위치 권한 → 백그라운드 위치 권한** 순서로 요청/안내. OS 설정 이동 후 복귀하면 실제 권한 재확인.
4. 권한 충족 시 `START` 대신 인디케이터 표시, 유효 GPS 위치를 기다림. **15초 대기 후 재시도/취소**는 초기 제안값.
5. GPS 준비 후 `3 → 2 → 1` 일회성 카운트다운. 중복 시작/카운트다운 방지.
6. 카운트다운 종료 시 DB 러닝 생성 및 실제 시간·거리 측정 시작 → Running 이동. 취소하면 러닝 생성 안 함.

MVP에서는 백그라운드 기록 사용을 시작 조건으로 한다. 토글이 OFF라면 다시 활성화하도록 안내하며, OS 권한이 없는 경우 앱이 임의로 권한을 켜지 않는다.

## 4. Running 화면 및 상태

- **기본 상태:** Bottom Sheet 확장(기록 약 70%, 지도 약 30%). 아래로 드래그하면 지도 중심(지도 약 70%), 위로 드래그하면 복귀. 비율은 기기별 조정.
- 패널 상태와 무관하게 운동 제어 가능. 지도 제스처와 시트 제스처는 충돌하지 않아야 함.
- `RUNNING`: **일시정지** 버튼 → `PAUSED`: **재개 / 종료** 버튼.
- `종료` 클릭 → `러닝을 종료하시겠습니까?` 확인 Alert. 취소 시 **PAUSED 유지**, 확인 시 DB 저장 성공 후 Run Result 이동.
- 상태: `READY → COUNTDOWN → RUNNING ↔ PAUSED → COMPLETED`.
- PAUSED에서는 운동 시간·거리 증가 없음. Resume 이후에는 새 GPS 경로 구간으로 처리.
- Bottom Sheet 확장/축소는 GPS 기록·운동 시간·DB 저장에 영향이 없어야 함.

## 5. GPS와 운동 기록 정책

- GPS 위도·경도·측정 시각·정확도를 검증하고, 중복·오래된 좌표·순간 이동·비현실적인 속도를 걸러낸다.
- **유효 GPS 좌표만** 거리 및 지도 경로에 반영. GPS 손실 시 시간은 계속 흐르되 거리는 보류, 재수신 시 손실 구간을 임의로 잇지 않는다.
- 일시정지 전후 경로는 분리하여 직선 연결을 방지한다.
- 거리 원본은 **m**, 시간은 **ms**, UI는 km / 분:초 / min/km로 표시. 평균 페이스는 유효 거리와 누적 운동 시간으로 계산하며 거리 0이면 측정 불가 표시.
- 화면 잠금·앱 전환 중에는 허용된 OS 범위에서 백그라운드 위치 추적을 시도한다. 강제 종료 후 계속 추적될 것을 보장하지 않는다.
- GPS 정확도·속도 임계값과 신호 손실 후 경로 분리 기준은 구현 직전 테스트 데이터로 결정한다.

## 6. SQLite 영구 저장 정책

**SQLite가 영구 데이터의 기준(Source of Truth)**이며, 실시간 UI 상태와 구분한다.

| 테이블 | 저장 내용 |
| --- | --- |
| `runs` | ID, 상태, 시작·종료 시각, 누적 운동 시간, 거리, 마지막 체크포인트, 경로 구간, 종료 사유(`normal`/`recovered`) |
| `run_locations` | ID, `run_id`(외래 키), 위도·경도·정확도·측정 시각·경로 구간·거리 증가분 |
| `app_settings` | 백그라운드 기록 사용 여부(앱 설정; OS 권한 상태와 별개) |

- `runs` 1 : N `run_locations`, 삭제 시 **ON DELETE CASCADE**.
- 평균 페이스는 중복 저장하지 않고 운동 시간과 거리로 계산.
- 카운트다운 종료 시 `runs` 생성. **유효 좌표를 받으면 좌표 삽입 + 누적 거리 갱신을 동일 Transaction**으로 저장.
- 운동 중 **약 5초마다 시간 체크포인트** 저장(초기 제안값). Pause/Resume 및 종료는 즉시 상태 저장. 실기기에서 주기·성능 확인.
- 상태 전환과 시간 계산에 필요한 기준 시각을 저장해 누적 시간이 중복 계산되지 않게 한다.
- DB 쓰기 중복·경쟁을 막고 실패 시 롤백. 종료 시 진행 중 쓰기 및 추적을 정리하고 **최종 저장 성공 후** 결과 표시. 실패 시 오류 및 재시도.
- 최초 스키마는 **Migration 001**. 배포 후 기존 데이터 보존이 필요한 변경에 후속 Migration 추가.

## 7. 앱 강제 종료 복구 — A안 확정

- 실행 시 `running` 또는 `paused`인 미완료 기록을 확인하고 살아 있는 추적 작업/쓰기부터 정리한다.
- 복구 UI: **기록 종료 및 저장 / 기록 삭제**. 이어하기는 MVP 제외.
- 마지막으로 **정상 저장된 시점까지**의 시간·거리·경로만 사용. 앱 중단 동안의 기록은 임의 보정하지 않는다.
- 종료하여 보존한 기록은 `completion_reason = recovered`로 구분한다.
- 복구 처리 전 새 러닝 시작을 제한. 단순 화면 잠금/앱 전환은 비정상 종료로 간주하지 않는다.

## 8. 설정·삭제·개인정보

- OS 위치 권한은 실제 시스템에서 조회·변경. Settings의 토글은 **앱 내부 백그라운드 기록 사용 여부**만 제어.
- 러닝 중 관련 설정 변경·전체 초기화 금지.
- Activity 휴지통 삭제 및 Settings 전체 초기화는 확인 Alert 후 실행. **운동 기록·경로 데이터**를 삭제하고 `app_settings`와 DB 스키마는 유지.
- 저장/삭제 실패를 성공으로 표시하지 않으며 종료·삭제 후 늦은 GPS 콜백의 쓰기를 방지.
- 실제 위치 경로는 민감 정보다. 로그·이미지·Git에 생활 반경의 원본 좌표를 노출하지 않는다.
- 서버 백업이 없으므로 앱/앱 데이터 삭제 시 기록을 잃을 수 있다.

## 9. 검증 완료 기준

| 시나리오 | 기대 결과 | 검증 |
| --- | --- | --- |
| START 연속 클릭 / GPS 대기 실패 | 중복 시작 없음, 타임아웃 시 재시도·취소 | 통합/E2E |
| 권한 거절·설정 복귀 | 실제 OS 권한 반영, 미충족 시 시작 차단 | Android 실기기 |
| 카운트다운 취소 | 러닝 기록 없음 | 통합/E2E |
| 거리·페이스·GPS 이상치 | 정확한 계산, 잘못된 좌표 제외 | TDD 단위 |
| Pause/Resume | 정지 구간 제외, 경로 분리 | 단위/통합 |
| 종료 Alert 취소/확인 | PAUSED 유지 / 저장 후 결과 이동 | 통합/Maestro |
| 좌표·거리 DB 쓰기 실패 | 둘 다 롤백 | SQLite 통합 |
| 앱 재실행·강제 종료 복구 | 기존 기록 유지, 체크포인트만 복구 | 통합/실기기 |
| Activity 상세와 결과 뒤로가기 | 각각 Activity / Home으로 복귀 | Maestro |
| 개별 삭제·전체 초기화 | 관련 좌표 삭제, 설정 유지 | SQLite 통합/E2E |
| 화면 잠금·앱 전환 | 지원 환경에서 위치 추적 확인 | Android 실기기 |

- **단위/통합 테스트**, **Maestro E2E**, **Android 실기기 테스트**는 서로 구분하여 기록한다.
- 테스트가 작성되었다는 사실과 실제 실행·통과를 혼동하지 않는다.

## 10. 구현 전 남은 세부 결정

- Android 시스템 뒤로가기로 Running 이탈 시 확인 UX
- GPS 필터링 정확도·속도·신선도 임계값
- 짧은/0km 러닝의 완료 기록 보관 여부
- GPS 준비 15초 대기, 운동 시간 5초 체크포인트를 실기기 결과로 보정

> 이 문서는 제품 기획 기준이다. **아키텍처, Zustand 사용 범위, 폴더 구조, Codex 규칙**은 다음 단계에서 `AGENTS.md`로 정의한다.
